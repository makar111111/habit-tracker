# Покращення трекера

Користувач погодив виконання рекомендованих покращень і доручив самостійно обрати деталі. Зміни виконуються у гілці `codex/tracker-reliability`. Поточні `.env`, `habits.db` та його копії не відкриваються й не змінюються; усі перевірки використовують підміну `get_session`.

## Рішення

Зберігаємо FastAPI, SQLite, React і спільний API для двох клієнтів. Розклад задається днями тижня при створенні звички; окремий режим тижневої квоти не потрібен для першої версії. Історія лишається доступною після архівування. Перед зміною наявної схеми застосунок створює узгоджену резервну копію SQLite; міграції версіонуються й перевіряються на копіях тестових баз.

## Контракт API

- Habit додає `start_date: date | null`, `weekdays: list[int]` (0=понеділок, 6=неділя; непорожній відсортований унікальний список), `archived_at: date | null`. Нові звички починаються сьогодні у часовому поясі користувача, або в явно задану минулу дату. Для старих звичок міграція бере найранішу відмітку, а за її відсутності — дату міграції. Відмітка заднім числом може посунути дату початку раніше. Розклад незмінний після створення, щоб редагування не переписувало історичний знаменник.
- `POST /habits` приймає name, description, start_date, weekdays. `PATCH /habits/{id}` приймає name, description, archived (boolean); null, порожня/пробільна назва й назва понад 100 символів відхиляються до запису. Порожній PATCH допустимий.
- `GET /habits` та `/stats` за замовчуванням виключають архів; `?include_archived=true` включає його. Окремі звички й їхні відмітки доступні власникові в архіві. Нові відмітки після дати архівування відхиляються. Відновлення прибирає archived_at.
- Формат HabitStats лишається сумісним. Серії рахуються за послідовними запланованими виконаннями; вихідні не обривають серію. Загальна кількість зберігає всю історію. Аналітика ділить виконані заплановані дні на дні розкладу між start_date, початком періоду та archived_at.
- UserPublic додає `timezone: string`, `reminder_hour: int` (0..23), `reminders_enabled: bool`. `PATCH /users/me` стає частковим і приймає ці поля та name. Часові пояси перевіряються через IANA ZoneInfo. `GET /users/me/today` повертає `{day: ISO-date}` у часовому поясі користувача.
- `GET /users/me/export` повертає завантажуваний JSON: version, exported_at, user, habits (разом з архівом), checkins. Дані обмежені власником, секретів немає.
- Для бота `GET /reminder-targets` (RequireBot) повертає telegram_id, timezone, reminder_hour, last_reminder_day для користувачів з увімкненими нагадуваннями. `POST /reminder-targets/{telegram_id}/sent` з `{day: ISO-date}` зберігає день успішної доставки. Бот перевіряє раз на хвилину й надсилає після заданої години лише раз за локальний день; невдалу доставку не позначає. Повтор після втрати відповіді на підтвердження можливий, це не гарантія exactly-once.
- `GET /health` перевіряє доступність БД без створення користувача. Вхід отримує атомарне одноразове споживання коду, очищення прострочених кодів та налаштування Secure для cookie. Некоректні заголовки повертають 401.

## Веб і бот

Форма нової звички містить дату початку й дні тижня. «Сьогодні» показує заплановані звички та окремо інші активні; прогрес враховує лише заплановані. Календар дозволяє ставити й знімати минулі відмітки з доступними підписами та захистом від повторних натискань. Архів має відновлення й доступну історію. Налаштування профілю містять час/пояс нагадувань та експорт. Аналітика і календар мають окремі стани завантаження, помилки й повторення; помилки ніколи не перетворюються на нулі. Веб і бот використовують локальну дату власника.

## Перевірки

Регресії некоректного PATCH і заголовків, ізоляція архіву й експорту, розклад та серії, часові пояси, персональні нагадування, ідемпотентність міграцій і відновлення резервної копії. Компонентні інтеграційні тести для помилок/календаря/архіву/налаштувань. Повний pytest, Vitest, TypeScript і production build; ручний прогін зібраної сторінки у браузері з тестовою базою. CI додатково запускає зібраний контейнер і перевіряє health, статичні файли та видачу коду входу з тестовими налаштуваннями.
