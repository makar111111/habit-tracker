# Трекер звичок

Невеликий вебзастосунок для відстеження щоденних звичок: список звичок,
відмітки виконання по днях, підрахунок серій і календар-хітмапа на 12 тижнів.

Навчальний проєкт на FastAPI + SQLite.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8000
```

Далі відкрити http://127.0.0.1:8000/

База даних `habits.db` створиться сама при першому запуску.

## Тести

```bash
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

41 тест, близько 0.4 секунди. Тести працюють з базою в оперативній пам'яті
й не торкаються `habits.db`.

## API

Інтерактивна документація — http://127.0.0.1:8000/docs

| Метод | Шлях | Опис |
|---|---|---|
| `GET` | `/habits` | список звичок |
| `POST` | `/habits` | створити звичку |
| `GET` | `/habits/{id}` | одна звичка |
| `PATCH` | `/habits/{id}` | змінити назву чи опис |
| `DELETE` | `/habits/{id}` | видалити звичку та її відмітки |
| `GET` | `/habits/{id}/checkins` | відмітки; фільтри `?since=` та `?until=` |
| `POST` | `/habits/{id}/checkins` | відмітити день (без тіла — сьогодні) |
| `DELETE` | `/habits/{id}/checkins/{day}` | зняти відмітку |
| `GET` | `/habits/{id}/stats` | статистика однієї звички |
| `GET` | `/stats` | статистика всіх звичок одним запитом |

## Структура

```
main.py            ендпоінти
models.py          опис даних (таблиці й моделі запитів)
database.py        підключення до SQLite
stats.py           обчислення серій — без залежностей від БД і HTTP
conftest.py        фікстури для тестів
test_stats.py      тести логіки
test_api.py        тести ендпоінтів
static/            сторінка застосунку (HTML + CSS + JS без фреймворків)
```

## Рішення, які варто пояснити

**Логіка окремо від інфраструктури.** `stats.py` не імпортує ні FastAPI,
ні SQLModel — лише роботу з датами. Тому його тести виконуються за 0.03 с
і не потребують ні бази, ні сервера.

**Серія не рветься опівночі.** `current_streak` вважається живою, якщо
відмічено сьогодні *або* вчора. Інакше двадцятиденний прогрес згорав би
о 00:01 за те, що людина ще спить.

**Унікальність продубльована в базі.** Ендпоінт перевіряє повтор і віддає
`409`, але обмеження `UNIQUE (habit_id, day)` стоїть і на рівні таблиці:
код можна випадково зламати при рефакторингу, базу — ні.

**`GET /stats` робить рівно два SQL-запити** незалежно від кількості звичок.
Це закріплено тестом `test_all_stats_does_not_scale_queries_with_habits`,
який лічить запити до бази.
