# CLAUDE.md

Інструкція для Claude Code по цьому проєкту: що це, як запускати, як тестувати, яких правил дотримуватись.

Опис проєкту, структура файлів і причина, чому бот ходить в API по HTTP
(а не в базу напряму) — див. `README.md`.

## Команди

Усі команди виконуються з кореня проєкту, з активованим `.venv`.

```bash
# активувати середовище (Windows)
.venv\Scripts\activate

# встановити залежності (requirements-dev.txt сам тягне requirements.txt)
pip install -r requirements-dev.txt

# запустити API (dev-сервер із автоперезапуском)
uvicorn main:app --reload

# запустити Telegram-бота (окремий термінал; потрібен .env з BOT_TOKEN і BOT_SECRET)
python -m bot

# усі тести
python -m pytest

# один файл або один тест
python -m pytest test_api.py
python -m pytest test_api.py::test_create_habit -v

# запуск у контейнерах (обидва сервіси одразу)
docker compose up -d --build
docker compose logs -f bot
docker compose down
```

Фронтенд живе окремим проєктом у `frontend/` (React + TypeScript + Vite):

```bash
cd frontend
npm install            # один раз після клонування
npm run dev            # розробка на :5173, API проксіюється на :8000
npm run build          # бойова збірка у frontend/dist
npm test               # тести (Vitest)
npx tsc --noEmit       # лише перевірка типів
npm run lint           # ESLint (правила хуків React, заборона export default)
npm run format         # Prettier: відформатувати весь фронтенд
```

Лінтери: `python -m ruff check .` для Python (правила й причини вибору —
у `ruff.toml`) і `npm run lint` для фронтенду. Обидва запускаються в CI
і мають проходити так само, як тести.

Форматери: `python -m ruff format .` для Python і `npm run format` для
фронтенду (налаштування — `frontend/.prettierrc.json`). CI перевіряє
форматування через `--check`. Коли файл редагує Claude, хук у
`.claude/settings.json` форматує й лінтить його автоматично.

Хук-запобіжник `.claude/hooks/guard_command.py` (PreToolUse на Bash і
PowerShell) блокує небезпечні команди ще до запуску: force push,
`reset --hard`, рекурсивне видалення, будь-яку згадку `habits.db`, запис
у `.env`, `docker compose down --volumes`. Якщо він заблокував потрібну
дію — не обходь його перефразуванням, а попроси людину виконати команду
самостійно. Нове правило — разом із випадком у `test_guard_hook.py`.

Хук `.claude/hooks/block_push_main.py` забороняє Claude пушити в `main`
(і `master`). Він розбирає аргументи push, а коли гілку не вказано —
питає git про поточну: `git push` на `main` теж заблоковано. Для змін,
які треба запушити, створюй окрему гілку; у `main` пушить людина.

## Вхід у вебверсію

Вебсторінка **вимагає входу**. Запит без автентифікації дістає `401` —
це нормальна поведінка, а не поломка.

Дві адреси, і плутати їх не варто: `http://127.0.0.1:8000/app/` — зібрана
версія (те, що побачить користувач), `http://localhost:5173` — режим
розробки Vite з миттєвим оновленням. Друга працює лише коли поруч
запущений `uvicorn`, бо всі запити до API вона проксіює на порт 8000.

Увійти можна двома способами:

1. **Через бота** (як у бойовому режимі): відкрити сторінку → «Увійти
   через Telegram» → підтвердити кнопкою в боті. Потрібні `SESSION_SECRET`
   і `BOT_USERNAME` у `.env`, і запущений бот.
2. **Режим розробки**: `ALLOW_LOCAL_USER=1` у `.env` — тоді запит без
   доказів вважається «локальним користувачем». Швидко для верстки, але
   це ОКРЕМИЙ акаунт зі своїми звичками, не твій Telegram-акаунт.

Після роботи в режимі розробки не забудь повернути `ALLOW_LOCAL_USER=`
порожнім: за замовчуванням він вимкнений, бо на сервері означав би
«хто дістався до порту — той і господар».

Якщо звички лишились на локальному акаунті з часів до появи бота —
перенести їх у Telegram-акаунт можна скриптом:

```bash
python migrate_merge_local_user.py            # показати план
python migrate_merge_local_user.py --apply    # виконати (робить копію бази)
```

## Правила кодингу

1. **Нова функціональність — тільки разом із тестом.** Додав ендпоїнт або хендлер бота — додай тест у відповідний `test_*.py`. Додав логіку у фронтенді — додай тест поруч із файлом (`*.test.ts`). Завдання не вважається завершеним, поки `python -m pytest` і `npm test` не проходять повністю.
2. **Жодних секретів у коді.** Токени, ключі та параметри підключення — тільки через `.env` і `config.py`. У репозиторій потрапляє лише `.env.example`.
3. **HTTP-заголовки — лише латиниця й цифри.** Вони за стандартом однобайтові: кирилиця в `X-Bot-Secret` чи подібному заголовку падає голим `UnicodeEncodeError` ще до відправки запиту. Дані, де кирилиця очікувана (імена людей, назви звичок), передавай тілом JSON, а не заголовком.
4. **Тест на конкурентність (`asyncio.gather` із двома одночасними запитами) потребує сесії бази НА ЗАПИТ, а не спільної на весь тест.** Спільна сесія SQLite під `asyncio.gather` даватиме `bad parameter or other API misuse` вряди-годи — флакі, а не стабільний збій. Патерн: тимчасова база у файлі (`tmp_path`) + `dependency_overrides`, що створює нову сесію в кожному виклику (як бойовий `database.get_session`). Приклад — фікстура `api` в `test_bot_api.py`.
5. **`hmac.compare_digest` порівнюй БАЙТИ, а не рядки.** На рядках із не-ASCII символами він кидає `TypeError`. Cookie й заголовки повністю в руках того, хто їх надсилає, тож кирилиця там — не екзотика, а найпростіший спосіб зронити сервер у `500` замість чесного `401`. Тобто `a.encode()` проти `b.encode()`. Знайдено тестом `test_garbage_cookie_is_rejected`.
6. **CSS-змінна в атрибуті `fill` чи `stroke` НЕ працює.** Ці атрибути SVG
не є CSS-оголошеннями, і браузер не розкриває в них `var(--accent)` —
лінія просто не намалюється, без жодної помилки в консолі. Кольори для
графіків читаються з обчислених стилів у JavaScript: хук
`useChartColors` у `frontend/src/lib/`. Він же стежить за `data-theme`
через `MutationObserver`, щоб графіки перефарбувалися при зміні теми.

7. **У фронтенді — тільки іменовані експорти** (як і в глобальних
правилах). Винятки вимушені: `vite.config.ts` і `eslint.config.js`, бо
інструменти читають саме `default`. Правило перевіряє ESLint. Там, де стороння бібліотека вимагає `default` —
наприклад `React.lazy` — місток пишеться явно:
`lazy(() => import("...").then((m) => ({ default: m.НазваКомпонента })))`.

8. **Від'ємні відступи в `margin` графіків Recharts обрізають підписи осі.**
`left: -24` економить місце, коли на осі однозначні числа, і псує все,
коли там `100%`. Підпис при цьому не зникає, а обрізається до `)%` —
помітити можна лише очима. Знайдено скріншотом, не тестом.

9. **`aria-selected` на звичайній кнопці не працює.** За специфікацією ARIA
цей атрибут дозволений лише на ролях `tab`, `option`, `row`, `gridcell`
і `treeitem`. У `<button>` неявна роль `button`, тож атрибут мовчки
ігнорується: вкладка підсвічена візуально, але для екранного диктора
нічим не відрізняється від сусідньої. Для вкладок — компонент `Tabs`
(повний набір: `tablist` / `tab` / `tabpanel`, стрілки, roving tabindex).
Для кнопок-перемикачів, що не відкривають панелей (період 30/90 днів) —
`aria-pressed`, він на кнопці дозволений.

10. **Помилки дій показує `MutationCache`, а не кожна дія окремо.**
Обробник `onError` у `createQueryClient` (`frontend/src/api/queryClient.ts`)
ловить УСІ мутації й кладе повідомлення в `errorBus`; показує `ErrorBanner`
угорі сторінки. Не додавай `try/catch` у компоненти — саме через них
у першій версії жодна помилка дії не була видима. Тести створюють клієнт
тією ж функцією, тому перевіряють справжню конфігурацію.

11. **Відмітки завантажуються ВІКНОМ, а не всі.** `CHECKIN_WINDOW_DAYS = 120`
у `hooks.ts`; період входить у ключ кешу, тож календар і аналітика ділять
одну відповідь. Наслідок, про який легко забути: підсумок «за весь час»
рахувати з цих даних НЕ МОЖНА — це вікно. Таке число бере `/stats`
(поле `total`, рахується в базі). Помилка була б правдоподібною: число
схоже на справжнє, поки звичці не виповниться пів року.

12. **`useEffect` синхронізує — не запам'ятовує.** Запис вибору в
`localStorage` живе в обробнику кліку, а не в ефекті. Коли вони були
разом (`applyTheme` робив і те, і те), сам факт відкриття сторінки
зберігав тему, ніби людина її обрала, — і системне налаштування
переставало впливати назавжди. Закріплено тестом «НЕ запам'ятовує тему,
поки людина нічого не обрала».

13. **Тести, які покладаються на локальний режим, вмикають його ЯВНО.** Фікстура `client` у `conftest.py` робить `monkeypatch.setattr(auth, "ALLOW_LOCAL_USER", True)`. Без цього рядка ~25 тестів у `test_api.py` отримали б `401`. Тести самого входу (`test_login.py`) навпаки використовують власну фікстуру `web` із вимкненим режимом — інакше перевіряти автентифікацію було б безглуздо.

## Що варто памʼятати

- Перед зміною схеми БД зроби копію `habits.db`.
- Не редагуй і не видаляй: `.env`, `habits.db`, `habits.db.*` — включно з резервними копіями на кшталт `habits.db.backup`, навіть якщо вони здаються зайвими.
- Файли бази даних не комітяться — вони мають бути в `.gitignore` (шаблон `habits.db*`, а не `*.db`: резервні копії закінчуються не на `.db`, і вужчий шаблон їх пропускає).
- **Жоден скрипт чи проба (зокрема від subagent'ів) не має торкатися `habits.db` напряму.** Запуск застосунку чи його ендпоінтів для перевірки — завжди з підміненою тимчасовою базою через `app.dependency_overrides[get_session]`, ніколи проти файлу в корені проєкту.
- Спілкуйся зі мною українською.
